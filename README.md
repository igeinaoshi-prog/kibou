# 希望休管理サイト

従業員が月ごとに希望休(出勤できない日)を申請し、管理者が一覧・上限人数・
公開状況を管理できるツールです。GitHub Pagesで公開し、データはFirebase
Firestore(無料枠)に保存されます。

- 従業員用ページ(ベトナム語): `employee/index.html`
- 従業員用ページ(日本語): `employee-jp/index.html`
- 管理者用ページ: `admin/index.html`(表示言語: 日本語)

GitHub Pagesで公開すると、URLはそれぞれ以下のようになります(例):

```
https://<ユーザー名>.github.io/<リポジトリ名>/employee/
https://<ユーザー名>.github.io/<リポジトリ名>/employee-jp/
https://<ユーザー名>.github.io/<リポジトリ名>/admin/
```

ベトナム語ページの従業員には `employee/` の個別リンク、日本語ページの
従業員には `employee-jp/` の個別リンク、管理者には `admin/` のURLを
それぞれ共有してください。

### 2つの従業員用ページの違い

| | `employee/`(ベトナム語) | `employee-jp/`(日本語) |
|---|---|---|
| 表示言語 | ベトナム語 | 日本語 |
| 1か月の日数上限 | あり(最大6日) | なし |
| 日ごとの人数上限(管理者設定) | あり(上限に達すると選択不可) | なし(常に選択可) |
| 送信回数 | 月1回のみ | 月1回のみ |

どちらのページも管理者用ページの単一の表(admin/)に統合して表示され、
Excel出力にも両方の従業員が含まれます。ただし、日ごとの人数上限
(「上限設定」)はベトナム語ページの従業員にのみ表示・適用されます。
日本語ページの従業員が希望休を送信した日も、集計上の「現在の希望者数」
には加算されるため、間接的にベトナム語ページ側の上限到達に影響する
点にご注意ください。

### 従業員ごとの個別リンク(必須)

どちらの従業員用ページにも、名前を選ぶプルダウンはありません。**必ず
`employee/?name=氏名` または `employee-jp/?name=氏名` の形式の、
本人専用リンクでアクセスする必要があります。** URLに `?name=氏名` が
付いていない場合や、その従業員リストに登録されていない名前の場合は、
エラーメッセージが表示され、カレンダーは使えません。

### 送信済みの希望休を取り消す(再送信を許可する)

管理者用ページの表で、送信済みの従業員には行の右端に「取消」ボタンが
表示されます。押すと確認ダイアログが出て、OKするとその従業員のその月の
送信データが削除されます。本人が個別リンクを開くと、再度希望休を選んで
送信できるようになります(月1回制限がリセットされる形です)。

管理者用ページには「従業員リストの管理」が2つあります。
- 「従業員リストの管理(ベトナム語ページ用)」に登録した名前は
  `employee/` の個別リンクが発行されます。
- 「従業員リストの管理(日本語ページ用)」に登録した名前は
  `employee-jp/` の個別リンクが発行されます。

それぞれの「リンクをコピー」ボタンで発行したURLを、メッセージアプリ
などで各従業員に個別に送ってください。従業員を追加・削除しても
ファイルの再アップロードは不要です。

## セットアップ手順

### 1. Firebaseプロジェクトを作成する

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントで
   ログインして「プロジェクトを追加」。無料の「Sparkプラン」で十分です。
2. 作成したプロジェクトの「プロジェクトの設定」(左上の⚙️) を開き、
   「マイアプリ」から「ウェブアプリを追加」(`</>` アイコン)。
3. アプリのニックネームは何でも構いません(例: `kibou-kyuu`)。
   「Firebase Hosting」の設定は不要なのでチェックしなくてOKです。
4. 表示される `firebaseConfig` の値(`apiKey`, `authDomain`, `projectId` など)
   をコピーし、このリポジトリの `firebase-config.js` に貼り付けて保存します。

### 2. Firestoreデータベースを有効化する

1. Firebaseコンソールの左メニューから「Firestore Database」を選択し、
   「データベースの作成」。
2. ロケーションは日本に近いもの(例: `asia-northeast1` 東京)を選択。
3. 最初は「テストモード」でも構いませんが、必ず後述のルールに置き換えてください。
4. 「ルール」タブを開き、このリポジトリの `firestore.rules` の内容を
   コピーして貼り付け、「公開」します。

### 3. GitHubにアップロードしてGitHub Pagesで公開する

1. GitHubで新しいリポジトリを作成し、このフォルダの内容をすべて
   アップロード(push)します。
2. リポジトリの「Settings」>「Pages」を開き、
   「Source」を `Deploy from a branch`、ブランチを `main`(または該当ブランチ)、
   フォルダを `/ (root)` に設定して保存します。
3. 数分待つと、上記の従業員用・管理者用URLでアクセスできるようになります。

### 4. 動作確認

1. まず管理者用URL(`admin/`)を開き、該当する「従業員リストの管理」から
   従業員名を登録します(ベトナム語ページ用・日本語ページ用は別々に
   登録します)。
2. 登録した従業員名の横にある「リンクをコピー」で、その人専用の
   URL(`employee/?name=氏名` または `employee-jp/?name=氏名`)を
   取得します。
3. そのURLを開き、希望休を送信できるか確認します(`employee/` や
   `employee-jp/` だけの、名前が付いていないURLではエラーになります)。
4. 管理者用ページの表にリアルタイムで反映されることを確認してください。

### Excelへの出力

管理者用ページの「📊 Excelをダウンロード」ボタンを押すと、表示中の月の
希望休一覧が本物のExcelファイル(`.xlsx`)としてダウンロードされます。
1行目が日付、2行目が各日の上限設定、3行目が現在の希望者数、4行目以降が
従業員ごとの希望休(×印)になっており、そのまま本社への提出資料や
シフト作成の元データとして使えます。

## データの持ち方(Firestore)

- `employees/list` … ベトナム語ページの従業員名のリスト `{ names: string[] }`
- `employeesJp/list` … 日本語ページの従業員名のリスト `{ names: string[] }`
- `requests/{従業員名}__{年-月}` … 各従業員の月ごとの希望休
  `{ employee, yearMonth, offDays: number[], updatedAt }`
  (どちらのページから送信されたかにかかわらず、同じコレクションに保存されます)
- `capacity/{年-月}` … 日ごとの上限人数設定 `{ limits: { "1": 3, "5": 2, ... } }`
  (ベトナム語ページの従業員にのみ適用されます)
- `settings/monthVisibility` … 非公開にした月の一覧 `{ closed: ["2026-11", ...] }`
  (両方のページに共通で適用されます)

## セキュリティに関する注意

`firestore.rules` は初期状態で「誰でも読み書き可能」になっています。
社内の限られたメンバーにのみURLを共有する運用を前提としています。
より厳密にアクセス制限したい場合は、Firebase Authenticationの導入
(特に管理者ページ側にログインを必須にする)を検討してください。
必要であれば追加の実装も可能です。
